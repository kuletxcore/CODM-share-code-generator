current branch was closed rather than merged.

## What the branch adds

1. `src/components/LookContactSheet.tsx` — every look plus the code being edited,
   graded onto a single frame. Collapsed it is three graded stills of that frame
   and a "+N more" cell; open it is a tile grid that fills one tile per animation
   frame. Tiles can load a look, copy it, or feed the look card.
2. `src/lib/codm.ts` — `gradePlan()` hoists per-zone constants out of the pixel
   loop; `paintGrade()` reuses the plan and skips zones that cannot change
   anything, so the reset code is free. Measured 1.42x at 960x439 and ~1.1 ms for
   a 168x108 tile.
3. `src/lib/grade.test.mts` — the original pixel loop kept as an oracle; asserts
   the optimised one is bit-identical on every shipped look plus 25 randomised
   settings, plus alpha preservation and the neutral short-circuit.
4. `scripts/sync-agent-instructions.mjs` — generates every agent-instruction file
   from `AGENTS.md`, so no tool gets stale rules. `npm run agents:check` fails CI
   on drift.
5. `.github/workflows/ci.yml` — the first CI in the repo: agents:check, typecheck,
   lint, test, build.

## Verified, and how

```bash
npm run check     # typecheck + lint + tests + agent-file drift -> exit 0
npm run build     # static export succeeds
npm run dev       # serves, no runtime errors
```

There is **no browser** available in the environment this was built in, so the
canvas code was checked two ways instead: the real grade maths was replayed
against a native canvas implementation (`@napi-rs/canvas`) to prove tiles paint
and crop correctly, and the layout was reviewed as a montage of genuinely graded
tiles. **What has not been seen is the actual rendered page in a browser.** First
task for the next person: open it and look.

Specifically worth eyeballing:

- the wall with a real phone screenshot uploaded (not just the sample scene);
- the collapsed teaser at 390 px wide;
- tile actions on a touch device, where hover does not exist;
- that dragging a slider only repaints the "your code" tile (it should feel
  instant, not laggy — if it lags, the queue is repainting more than one tile).

## Known gaps, ranked

These were identified during review and deliberately left undone. Each is a real
defect, not a preference.

1. **The codec still accepts junk.** `decode()` in `src/lib/codm.ts` only checks
   segment count and finiteness, so `0x10`, `1e3`, a whitespace segment, preset
   `99` and `shadowPos 99999` are all accepted and quietly coerced. The strict
   version (with `SEGMENT_RANGES`) existed in the closed PR #24 and should be
   re-applied. **Regression to avoid: negative brightness is legal** and most
   shipped looks use it.
2. **A clean clone does not typecheck.** `next-env.d.ts` is gitignored and
   `LayoutProps<'/'>` is generated by the build, so `tsc --noEmit` fails before
   `next build` has run. `src/app/layout.tsx` already types `children`
   explicitly, which is what makes the current `npm run typecheck` pass — keep it
   that way, or track `next-env.d.ts`.
3. **Cancelling the share sheet downloads the card.** `saveCard()` in
   `src/components/ImportGuide.tsx` treats a user cancel (`AbortError`) as a
   failure and falls through to a PNG download, which on iOS/Android writes to the
   photo library after the user said no.
4. **The gallery stage is an autoplay live region.** `aria-live="polite"` on the
   stage plus a 7 s rotation means a screen reader reads a new look name forever.
   `role="tab"` elements also have no accessible name.
5. **`analyse()` reports confident values for tones the image does not contain.**
   A pure white frame produces three non-neutral zones, because empty bands
   divide by a `|| 1` guard.
6. **No `og:`/`twitter:` metadata.** Every shared link renders as a bare row. The
   look-card renderer already produces exactly 1200x630, so a static OG image is
   cheap.
7. **`history.replaceState` is unguarded** and the `#c=` read is unanchored.

## Conventions a newcomer will trip over

- Run `npm run check` before committing; CI runs the same steps and will fail on
  stale agent files.
- **Do not hand-edit `CLAUDE.md`, `GEMINI.md`, `CONVENTIONS.md`,
  `.github/copilot-instructions.md` or `.cursor/rules/agents.mdc`.** They are
  generated. Edit `AGENTS.md` and run `npm run agents:sync`.
- Read `DESIGN.md` before any UI change. It is the contract, not a suggestion.
- Tests are `*.test.mts` beside the code, using `node:test` with no runner
  dependency. Adding a test framework needs a reason.
- `next dev` rewrites its own block inside `AGENTS.md`. Commit it with your work
  so the tree stays clean.
